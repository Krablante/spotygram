# Устройство приложения

[Документация](README.ru.md) · [English](architecture.md) · **Русский**

Spotygram работает в одном Android-процессе и одном модуле приложения.
Он напрямую подключается к Telegram и читает аудио из локальных файлов.
Между плеером и данными нет собственного сервера или локального HTTP-прокси.

```text
Compose UI ── SpotygramApp ── Library / SQLite
                   │
                   ├── Telegram / TDLib ── серверы Telegram
                   │
                   ├── PlaybackService / Media3
                   │         └── TelegramDataSource ── загруженные части файла
                   │
                   └── AppUpdates ── релизы GitHub
```

## Кто за что отвечает

`SpotygramApp` координирует действия пользователя, поиск музыки и импорт.
`Telegram` владеет экземпляром TDLib, авторизацией, JSON-запросами и потоком
обновлений. `Library` хранит музыкальный индекс и публикует неизменяемые
снимки для интерфейса. Экраны не читают базу TDLib напрямую.

`PlaybackService` управляет ExoPlayer и очередью. Интерфейс использует
MediaController для управления воспроизведением, а изменения полной очереди
передаёт сервису внутри процесса. `DownloadService` последовательно выполняет
явные скачивания как видимый foreground-сервис. Для проверки обновлений
и очистки кэша отдельные службы не нужны.

## Из сообщения в музыкальную запись

Трек Telegram определяется парой ID чата и сообщения. Идентификатор файла
TDLib действует в текущем процессе; после перезапуска нужное сообщение
при необходимости разрешается заново. Несколько сообщений могут ссылаться
на одно аудио — их отдельные идентификаторы сохраняются в каталоге.

Обнаружение музыки проходит страницы аудио и документов до конца курсора,
а не до первой короткой страницы. У каждого фильтра есть курсор истории
и отметка новых сообщений: прерванная загрузка продолжается без пропусков.
Серверный поиск тоже обходит все страницы. Индексация собирает метаданные,
но не скачивает заранее каждый аудиофайл.

В каталог попадают аудиосообщения Telegram и документы с подходящим MIME-типом
или расширением. Голосовые и видео исключены. После скачивания документа
название и длительность могут дополняться встроенными метаданными.
Обложки берутся из миниатюр Telegram или самого файла; при их отсутствии
показывается статичная плитка.

`LibraryState` кэширует поиск по ID и группы локальных файлов на время жизни
снимка. **На телефоне** объединяет непустые локальные пути после применения
поиска и фильтра источника. Настройки считают размер и число файлов по той же
коллекции. Хэширования содержимого и объединения по названию нет. Любимые,
подсветка текущей песни и запрет её удаления учитывают все ссылки на файл.
Отмена возвращает точный прежний набор любимых. Новая очередь из локального
списка не содержит повторных ссылок на один файл; уже составленная вручную
очередь не переписывается незаметно для пользователя.

## Большая очередь и маленькая медиасессия

Полная логическая очередь остаётся внутри сервиса. Медиасессия Android видит
не более трёх физических записей: предыдущую, текущую и следующую.
Сдвиг этого окна откладывается до завершения callback перехода Media3:
синхронное изменение внутри него может передать контроллерам несогласованное
состояние очереди.

Записи очереди используют индексы исходной подборки, а не только ID трека:
«Слушать следующим» может намеренно добавить повтор. Перемешивание строит
перестановку Фишера — Йетса. Повтор всей подборки готовит новый проход,
не повторяя сразу песню на границе. Для возврата хранятся не более двух проходов.

Абсолютный рандом независимо выбирает следующий индекс, включая текущую
песню. Он хранит максимум 32 прошлых выбора, текущий и один следующий.
«Назад» идёт по этой истории. Явный следующий трек заменяет подготовленный
случайный выбор; повтор одного остаётся доступен. Встроенный shuffle
ExoPlayer выключен: правилами порядка управляет сам сервис.

Полный снимок очереди записывается только при изменении её состава или
структуры. Позиция, режим и курсор находятся в отдельных настройках,
связанных с очередью версией снимка. Один IO-писатель сохраняет последнее
состояние, пропуская уже устаревшие промежуточные. При запуске позиция
восстанавливается на паузе; тики прогресса и переходы рандома не переписывают
полный список песен.

## Файлы и сессия

`TelegramDataSource` читает готовые диапазоны прямо из загружаемого TDLib
файла. Недостающие части ждут обновлений с таймаутом. Второго медиакэша нет.
Полностью скачанные файлы остаются для офлайна; автоматическая очистка TDLib
отключена.

Копия после прослушивания и файл, явно скачанный пользователем, не разделены.
`MusicCache` запрашивает размер только при открытии своего экрана или
по кнопке обновления. Подтверждённая очистка просит TDLib освободить хранилище
аудио и документов, исключая импорт. Сначала останавливаются плеер и загрузки,
затем отсутствующие пути сверяются одной транзакцией SQLite. Любимые,
плейлисты и вход сохраняются. Логическая очередь восстанавливается на паузе
без недоступных записей. Поздние обновления загрузок проверяют наличие файла,
прежде чем снова объявить его доступным офлайн.

Удаление импортированного файла сначала убирает его вхождения из очереди,
затем запись каталога. Удаление копии Telegram сохраняет ссылку на сообщение.
При удалении источника скрываются его незагруженные треки, кроме любимых
и участников плейлистов. Если оригинал недоступен, вернуть удалённую копию
из Telegram не получится.

Ключ базы TDLib случайный и обёрнут AES-GCM через Android Keystore.
Резервное копирование Android отключено. Аудио и каталог лежат в приватном
хранилище приложения — это не отдельное шифрование каждого файла.
Выход удаляет записи Telegram и ссылки на них в плейлистах; импорт остаётся.
Чужие сессии не используются, сетевые данные не записываются в логи.

## Интерфейс и расход ресурсов

Compose отображает четыре раздела и запоминает последний открытый.
Русский и английский заданы ресурсами Android; на Android 13+ язык можно
выбирать отдельно для приложения. Правки плейлистов и пакетные операции
используют транзакции. Списки ленивые; обложки запрашиваются максимум
двумя параллельными задачами с низким приоритетом TDLib.

SQLite, импорт и разбор страниц работают вне UI-потока. При индексации
снимки библиотеки публикуются не чаще двух раз в секунду плюс по завершении.
Таймеры прогресса принадлежат видимым компонентам плеера, а не всему экрану.
О смене сети TDLib узнаёт через callback Android, без опроса по таймеру.
Целевой буфер — 15–30 секунд, порог старта — одна секунда, повторной
буферизации — две. Это настройки, а не измеренная гарантия скорости телефона.

## Проверка релизов

`AppUpdates` хранит небольшой StateFlow и отдельные настройки. `onStart`
Activity может запустить один запрос без авторизации к фиксированному
GitHub endpoint последнего релиза. Автоматические попытки разделены
сохраняемым интервалом 24 часа, ручные — минутой с учётом сохранённого
ограничения GitHub. Время попытки записывается на IO до запроса. Флаг
в основном потоке не даёт запустить параллельную проверку; после ошибки
запрос автоматически не повторяется. Перевод часов назад обновляет отметку времени
и пропускает эту попытку.

ETag/304 позволяет использовать сохранённые данные релиза. Таймауты
подключения/чтения — 5/8 секунд, предел ответа — 256 КиБ, перенаправления
запрещены. Принимаются обычные, не черновые и не предварительные релизы
с тегом `vMAJOR.MINOR.PATCH` и загруженным APK для архитектуры устройства.
Версии сравниваются численно. Ссылка строится внутри фиксированного
репозитория, а не берётся из произвольного URL ответа. Правила имён файлов
описаны в [инструкции по сборке](build.ru.md).

Новая версия появляется закрываемой строкой в библиотеке. Скрытие сохраняется
для этой версии, а ссылка остаётся в настройках. Автоматические ошибки
и отсутствие обновлений не показываются. Планировщика, фоновых пробуждений,
загрузчика APK и разрешения на установку нет. GitHub видит IP подключения
и версию приложения, но не аккаунт Telegram или музыкальную библиотеку.

## Проверки и границы

[Журнал проверок](verification.md) разделяет наблюдения и непроверенные
сценарии. Чтение кода не заменяет успешный вход в аккаунт, удалённую загрузку
или измерение на физическом телефоне. Сейчас поддерживаются один
Telegram-аккаунт и две архитектуры Android; секретные чаты, голосовые
сообщения и синхронизация плейлистов не входят в возможности приложения.
