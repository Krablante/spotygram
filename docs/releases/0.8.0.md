# Spotygram 0.8.0 — не сохранять прослушанное

В настройках появился необязательный режим **«Не сохранять прослушанное»**.
Он выключен по умолчанию. Новые копии для прослушивания становятся временными:
плеер защищает текущий, предыдущий и подготовленный следующий файлы, а также
все открытые чтения. Более старые временные копии удаляются через TDLib,
когда больше не нужны. Для возврата к ним может понадобиться интернет.

- Старые локальные файлы, импорт и явные скачивания сохраняются.
- Временные копии отмечены часами и не попадают в «На телефоне» и его счётчик.
- **«Сохранить на устройстве»** в плеере или меню оставляет временную копию
  без повторного скачивания, включая другие ссылки на тот же файл.
- Отключение режима сохраняет оставшиеся копии; удалённые не восстанавливает.
- Журнал временных файлов переживает перезапуск. При ошибке очистку можно
  повторить из настроек; фонового таймера или дополнительного сервиса нет.

Telegram по-прежнему использует временные файлы на диске: это не RAM-only
стриминг и не строгая квота хранилища. Ручная **«Очистить кэш музыки»**, как и
раньше, удаляет также явно скачанные копии Telegram после подтверждения.

Проверки интерфейса и локального состояния описаны в
[verification record](../verification.md). Авторизованное удалённое
воспроизведение и удаление TDLib в этом цикле не подтверждены: официальный
тестовый DC отверг документированный код входа. Рабочий аккаунт не использовался.

## English

New optional **Do not keep played tracks** setting, off by default. New playback
copies become temporary; the previous/current/prepared-next files and all open
readers remain protected. Older temporary copies are removed through TDLib.
Going back may require another download.

Existing local files, imports and explicit downloads remain saved. Temporary
copies have a clock icon and do not count as **On device**. **Save on device**
keeps a copy and its aliases without downloading again. Disabling the mode keeps
remaining copies, not already removed ones. A persistent ownership journal and
event-driven cleanup handle recovery, with manual retry when cleanup is deferred.

TDLib still uses temporary disk files; this is not RAM-only streaming or a hard
storage limit. Confirmed global cache cleanup still includes explicit Telegram
downloads. Authenticated remote playback/deletion was not verified in this cycle
because the official test DC rejected its documented login code; no production
account was used.
