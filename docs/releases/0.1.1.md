# Spotygram 0.1.1 — Вся музыка

Исправляет остановку на первых 100 треках чата, убирает лишние ожидания и обновляет перемешивание. Репозиторий и релиз остаются приватными.

**Для телефона: `spotygram-0.1.1-arm64.apk`.** Установи поверх 0.1.0, не удаляя приложение. Ключ подписи и `app.spotygram` сохранены; повторно добавлять чаты не нужно. После подключения Telegram приложение автоматически продолжит историю существующих источников.

## Что изменилось

- Вся доступная история музыки загружается автоматически. 100 сообщений — размер страницы Telegram, а не предел на чат. Найденные треки доступны сразу; аудиофайлы при индексации не скачиваются.
- Курсоры истории сохраняются после каждой страницы. Прерванное обновление новых сообщений не пропускает оставшиеся страницы. Поиск в чатах тоже проходит все страницы совпадений.
- Музыка больше не ждёт загрузки списка чатов после входа. Сам список показывается постепенно и использует готовые данные TDLib.
- Обложки загружаются по мере отображения вместо массового скачивания всей библиотеки. Известные в текущей сессии файлы не разрешаются заново при каждом запуске и перемотке.
- Смена сети передаётся TDLib через Android callback, история возобновляется при переподключении. Таймауты теперь показывают сообщение вместо тихого прекращения операции. Порог стартового буфера снижен до одной секунды; фактическая задержка зависит от сети и формата.
- «Перемешать и слушать» случайно выбирает первый трек и весь порядок подборки. Fisher–Yates использует системный `SecureRandom`, без фиксированного seed и весов по популярности. Треки не повторяются внутри прохода; повтор всей очереди обновляет порядок, а перезапуск приложения сохраняет его.
- «Слушать следующим» работает и при перемешивании. На паузе нет таймера сохранения позиции; во время воспроизведения не пересобирается JSON всей очереди каждые пять секунд.

## Границы проверки

Результаты сборки и ручной проверки записаны в `docs/verification.md`. Полная история авторизованного Telegram-аккаунта, восстановление удалённого потока при смене сети и скорость на физическом ARM64-телефоне требуют проверки на устройстве; локальное воспроизведение не подменяет эти сценарии.
