# Сборка и выпуск Spotygram

[Документация](README.ru.md) · [English](build.md) · **Русский**

Если хочешь только слушать музыку, скачай подписанный APK из
[релизов](https://github.com/Krablante/spotygram/releases/latest).
Это руководство для самостоятельной сборки и сопровождения приложения.
Первая сборка компилирует TDLib и OpenSSL, последующие используют готовые
нативные библиотеки.

## Подготовить окружение

Нужны Linux, полный JDK 21, Android SDK platform 36, build tools 36,
NDK `28.2.13676358`, CMake, Ninja, gperf, Perl, C++-компилятор, Git и Make.
Gradle Wrapper фиксирует Gradle 8.14.3.

Исходники проекта и рабочие данные сборки хранятся отдельно.
`SPOTYGRAM_STATE` содержит скачанные нативные исходники, результаты сборки,
кэши и приватные настройки. Выбери для него каталог вне репозитория:

```sh
export ANDROID_HOME=/path/to/android-sdk
export SPOTYGRAM_STATE=/path/to/private/spotygram-state
```

Создай в нём `telegram.env` с данными своего приложения, полученными
на [my.telegram.org](https://my.telegram.org). Оставь доступ к файлу только
своему пользователю. Замени оба значения:

```dotenv
TELEGRAM_API_ID=YOUR_NUMERIC_API_ID
TELEGRAM_API_HASH=YOUR_API_HASH
```

Эти данные определяют приложение, а не авторизованного пользователя.
Они попадают в APK и могут быть извлечены из него. Сессии пользователей
и токены ботов в этот файл не помещают; сам файл не добавляют в Git.

## Собрать APK для разработки

Из корня репозитория запусти:

```sh
bash tools/build.sh debug
```

Скрипт при необходимости собирает TDLib из коммита
`d1085f9cebc5a62379991ae1652673954f229c1f` и OpenSSL `openssl-3.5.6`,
затем собирает приложение. Нативные библиотеки создаются для ARM64
и x86-64 с поддержкой страниц 16 КБ.

Готовые файлы находятся в `$SPOTYGRAM_STATE/build/app/outputs/apk/debug/`:
`app-arm64-v8a-debug.apk` для ARM64-телефона и `app-x86_64-debug.apk`
для эмулятора x86-64.

Нативную сборку, Gradle и эмулятор запускай последовательно. По умолчанию
сборки используют два рабочих процесса, Gradle — heap 2 ГБ. Число рабочих
процессов нативной сборки задаёт `SPOTYGRAM_JOBS`. На общей машине стоит
дополнительно ограничивать CPU и память. Для обычных правок интерфейса
достаточно debug; более медленную оптимизированную release-сборку запускай
после завершения правок.

## Подписать релиз

Для своей сборки создай ключ один раз и сохрани его резервную копию.
Будущие обновления должны быть подписаны тем же ключом. При сопровождении
официального Spotygram используй существующий ключ, не создавай замену.

```sh
keytool -genkeypair -keystore "$SPOTYGRAM_STATE/release.jks" \
  -alias spotygram -keyalg RSA -keysize 3072 -validity 10000
```

В приватном `$SPOTYGRAM_STATE/signing.properties` укажи
`storePassword=YOUR_PASSWORD`. Пароль хранилища и ключа должен совпадать.
Ни ключ, ни настройки подписи не должны попадать в Git.

```sh
bash tools/build.sh release
```

Результаты находятся в `$SPOTYGRAM_STATE/build/app/outputs/apk/release/`:
`app-arm64-v8a-release.apk` и `app-x86_64-release.apk`. Раздельные APK
не заставляют телефон скачивать ненужную вторую архитектуру. Перед выпуском
проверь подпись через Android SDK `apksigner verify --verbose` и вычисли SHA-256.

## Опубликовать обновление

Репозиторий и релизные APK публичны. API-настройки, сессии и закрытый ключ
подписи остаются приватными; GitHub-токен в приложение не встраивается.

При выпуске увеличивай `versionCode` Android и числовой `versionName`.
Создай черновик релиза с тегом `vMAJOR.MINOR.PATCH` и загрузи:

- `spotygram-MAJOR.MINOR.PATCH-arm64.apk`;
- `spotygram-MAJOR.MINOR.PATCH-x86_64.apk`;
- `SHA256SUMS`.

Проверь загрузку файлов и только затем опубликуй обычный релиз, отметив его
как Latest. Так приложение не увидит выпуск с ещё не загруженным APK.
Не меняй существующие идентификатор приложения и ключ подписи.
Проверка обновлений использует публичный `/releases/latest`, сравнивает
числовые версии и проверяет наличие подходящего APK. Prerelease в этот
канал обновлений не входит.

Установщик внутри приложения использует SHA-256 из поля `digest` файла GitHub
и его точный размер. Перед передачей Android проверяются пакет, версия и
действующие сертификаты подписи. Перед публикацией сравни загруженные digest
с локальными APK. Сборки с другим ключом, включая debug, намеренно не принимают
официальный релиз как обновление. Установщик получает доступ только к приватной
копии APK; разрешение на доступ ко всему хранилищу не требуется.

## Проверять изменения

Debug использует ID `app.spotygram.dev`, релиз — `app.spotygram`.
Они устанавливаются рядом и не разделяют сессию. Только debug может
использовать тестовые серверы Telegram через `-PtelegramTestDc=true`.
Не переключай существующую debug-установку между серверами без очистки
данных именно этой debug-установки.

Проверки выполняются вручную: интерфейс, системный выбор файлов,
`adb logcat`, `adb shell dumpsys media_session`, `dumpsys meminfo`
и `dumpsys gfxinfo`. Тестового набора и генерируемых тестовых заготовок
в проекте нет. Наблюдения и ограничения записываются
в [журнал проверок](verification.md).

Версии зависимостей и контрольная сумма Gradle зафиксированы. Для сборки
не нужны чужая медиатека, сессия Telegram или машинные пути из Git.
