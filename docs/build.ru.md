# Сборка и выпуск Spotygram

[Документация](README.ru.md) · [English](build.md) · **Русский**

Если хочешь только слушать музыку, скачай APK или архив для компьютера из
[релизов](https://github.com/Krablante/spotygram/releases/latest).
Это руководство для самостоятельной сборки и сопровождения приложения.
Первая Android-сборка компилирует TDLib и OpenSSL, последующие используют готовые
библиотеки. Desktop скачивает закреплённые сборки TDLib/libmpv и проверяет их контрольные суммы.

## Подготовить окружение для Android

Нужны Linux, полный JDK 21, Android SDK platform 37, build tools 36.0.0,
NDK `28.2.13676358`, CMake, Ninja, gperf, Perl, C++-компилятор, Git и Make.
Gradle Wrapper фиксирует Gradle 9.3.1, Android Gradle plugin 9.1.1 и Kotlin 2.4.20.
Приложение по-прежнему использует targetSdk 36 и поддерживает Android 8+.

Исходники проекта и рабочие данные сборки хранятся отдельно.
`SPOTYGRAM_STATE` содержит скачанные нативные исходники, результаты сборки,
кэши и приватные настройки. Оба модуля Gradle используют один каталог. Без явного
значения Gradle берёт `~/.local/state/spotygram`; Android-скрипт также учитывает
`XDG_STATE_HOME`. При смене инструментов задавай `SPOTYGRAM_STATE` явно. Скрипты
отклоняют state внутри исходников до генерации файлов или распаковки зависимостей.
Выбери каталог вне репозитория:

```sh
export ANDROID_HOME=/path/to/android-sdk
export SPOTYGRAM_STATE=/path/to/private/spotygram-state
```

Создай в нём `telegram.env` с данными своего приложения, полученными
на [my.telegram.org](https://my.telegram.org). Оставь доступ к файлу только
своему пользователю. Замени оба значения:

```dotenv
TELEGRAM_API_ID=YOUR_NUMERIC_API_ID
TELEGRAM_API_HASH=YOUR_API_HASH
```

Эти данные определяют приложение, а не авторизованного пользователя.
Они попадают в APK и могут быть извлечены из него. Сессии пользователей
и токены ботов в этот файл не помещают; сам файл не добавляют в Git.

## Собрать APK для разработки

Из корня репозитория запусти:

```sh
bash tools/build.sh debug
```

Скрипт при необходимости собирает TDLib из коммита
`d1085f9cebc5a62379991ae1652673954f229c1f` и OpenSSL `openssl-3.5.6`,
затем собирает приложение. Нативные библиотеки создаются для ARM64
и x86-64 с поддержкой страниц 16 КБ.

Готовые файлы находятся в `$SPOTYGRAM_STATE/build/app/outputs/apk/debug/`:
`app-arm64-v8a-debug.apk` для ARM64-телефона и `app-x86_64-debug.apk`
для эмулятора x86-64.

Нативную сборку, Gradle и эмулятор запускай последовательно. По умолчанию
сборки используют два рабочих процесса, Gradle — heap 2 ГБ. Число рабочих
процессов нативной сборки задаёт `SPOTYGRAM_JOBS`. На общей машине стоит
дополнительно ограничивать CPU и память. Для обычных правок интерфейса
достаточно debug; более медленную оптимизированную release-сборку запускай
после завершения правок.

## Подписать релиз

Для своей сборки создай ключ один раз и сохрани его резервную копию.
Будущие обновления должны быть подписаны тем же ключом. При сопровождении
официального Spotygram используй существующий ключ, не создавай замену.

```sh
keytool -genkeypair -keystore "$SPOTYGRAM_STATE/release.jks" \
  -alias spotygram -keyalg RSA -keysize 3072 -validity 10000
```

В приватном `$SPOTYGRAM_STATE/signing.properties` укажи
`storePassword=YOUR_PASSWORD`. Пароль хранилища и ключа должен совпадать.
Ни ключ, ни настройки подписи не должны попадать в Git.

```sh
bash tools/build.sh release
```

Результаты находятся в `$SPOTYGRAM_STATE/build/app/outputs/apk/release/`:
`app-arm64-v8a-release.apk` и `app-x86_64-release.apk`. Раздельные APK
не заставляют телефон скачивать ненужную вторую архитектуру. Перед выпуском
проверь подпись через Android SDK `apksigner verify --verbose` и вычисли SHA-256.

## Собрать desktop-пакеты

Собирай на целевой системе с **JDK 21**, **Python 3.12+** и CLI OpenSSL 3
(на macOS — `brew install openssl@3`).
Windows и Linux используют x86-64; для macOS есть отдельные сборки x86-64 и ARM64.
Установщики создаёт JDK `jpackage`: на Windows нужен **WiX Toolset 3**, на Ubuntu
для DEB — **fakeroot**. Workflow подготавливает эти инструменты.
Компиляция нативных исходников и Node.js не нужны. `SPOTYGRAM_STATE` должен
оставаться вне репозитория. Используй тот же `telegram.env` или переменные
окружения `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`.

```sh
python3 tools/build-desktop.py --image-only
```

На Windows используй `python` вместо `python3`. Скрипт запускает два рабочих
процесса Gradle, компилятор Kotlin внутри Gradle и одноразовый daemon.
Готовое приложение находится в `$SPOTYGRAM_STATE/build/desktop/distributions/main/app/`.
У встроенного Java-рантайма максимум heap — 256 МиБ; это ограничение не включает
нативную память Telegram, аудио и графики. Оба платформенных модуля компилируют
`shared/` напрямую: отдельный desktop-интерфейс или алгоритмы очереди не нужны.

TDLib берётся из `prebuilt-tdlib` 0.1008067.0, LGPL-сборка libmpv 0.41.0 — из
закреплённого релиза `jason-yau/mpv-prebuilt`. URL и контрольные суммы находятся
в `tools/desktop-dependencies.py`. Загрузки, распаковка и библиотеки остаются
в state. В приложение попадают только нативные зависимости его платформы.
macOS-пакет получает ad hoc подпись и общую публичную версию; нотариализация
Apple не настроена.

Для нового форка создай Ed25519-ключ обновлений один раз:

```sh
python3 tools/package-desktop.py --init-key
```

Команда сохраняет закрытый ключ в `$SPOTYGRAM_STATE/desktop/signing/release-private.pem`
и выводит публичный. Только публичный ключ помещается в
`desktop/src/main/resources/update-key.pub`. **При сопровождении официального
Spotygram сохраняй существующие закрытый и публичный ключи.** Сделай приватные
резервные копии desktop-ключа и Android keystore. Затем собери установщик и подписанный переносной архив:

```sh
python3 tools/build-desktop.py
```

MSI, DEB или DMG, его отдельная `.sig` и переносной архив находятся в
`$SPOTYGRAM_STATE/releases/VERSION/`. В каждом архиве — полное
приложение, манифест файлов и подпись Ed25519. Упаковка требует существующий
закрытый ключ, совпадающий с доверенным публичным ключом приложения. При установке распаковывай
весь архив для переносного запуска; музыка и настройки хранятся отдельно в данных пользователя.
Установщики упаковывают тот же готовый образ. Windows использует постоянный MSI
upgrade UUID и по умолчанию `%LOCALAPPDATA%\SpotygramApp`; не меняй этот UUID.
Пакет Ubuntu владеет `/opt/spotygram` и записью меню приложений. В DMG находятся
подписанное приложение и ссылка Applications. Только образ установщика получает
ресурс `installation`: он выбирает обновление пакетом вместо замены архива.
Подпись установщика связывает `Spotygram installer\nИМЯ_ФАЙЛА\nSHA256\n` с прежним
ключом Ed25519. Эта подпись издателя отличается от Windows Authenticode и
Apple notarization, которые не настроены.

GitHub Actions **Desktop release assets** собирает четыре desktop-платформы
на их штатных runners. Добавь секреты репозитория `TELEGRAM_API_ID`,
`TELEGRAM_API_HASH` и `DESKTOP_RELEASE_KEY` с закрытым PEM, запусти workflow
и скачай четыре артефакта. Он готовит файлы, но сам не публикует релиз.

## Опубликовать обновление

Репозиторий и релизные файлы публичны. API-настройки, сессии и закрытые ключи
остаются приватными; GitHub-токен в приложение не встраивается.

При выпуске увеличивай общую числовую версию в корневом `build.gradle.kts`
и возрастающий `versionCode` Android.
Создай черновик релиза с тегом `vMAJOR.MINOR.PATCH` и загрузи:

- `spotygram-MAJOR.MINOR.PATCH-arm64.apk`;
- `spotygram-MAJOR.MINOR.PATCH-x86_64.apk`;
- `spotygram-MAJOR.MINOR.PATCH-windows-x64.zip`;
- `spotygram-MAJOR.MINOR.PATCH-linux-x64.tar.gz`;
- `spotygram-MAJOR.MINOR.PATCH-macos-x64.zip` и `spotygram-MAJOR.MINOR.PATCH-macos-arm64.zip`;
- `spotygram-MAJOR.MINOR.PATCH-windows-x64.msi` и его `.msi.sig`;
- `spotygram-MAJOR.MINOR.PATCH-linux-x64.deb` и его `.deb.sig`;
- `spotygram-MAJOR.MINOR.PATCH-macos-x64.dmg` и `spotygram-MAJOR.MINOR.PATCH-macos-arm64.dmg`, каждый со своей `.dmg.sig`;
- `SHA256SUMS` для всех пакетов, переносных архивов и отдельных подписей.

Сравни размер и GitHub SHA-256 digest каждого загруженного файла с локальным
и только затем опубликуй полный обычный релиз как Latest.
Сохраняй оба ключа подписи и идентификатор приложения Android.
Проверка обновлений использует публичный `/releases/latest`, сравнивает
числовые версии и проверяет точное имя файла для платформы. Prerelease в этот
канал обновлений не входит.

Установщик внутри приложения использует SHA-256 из поля `digest` файла GitHub
и его точный размер. Перед передачей Android проверяются пакет, версия и
действующие сертификаты подписи. Перед публикацией сравни загруженные digest
с локальными APK. Сборки с другим ключом, включая debug, намеренно не принимают
официальный релиз как обновление. Установщик получает доступ только к приватной
копии APK; разрешение на доступ ко всему хранилищу не требуется.

Установленный desktop проверяет digest пакета и отдельную подпись релиза, затем
открывает `msiexec`, Finder или установщик Linux. Приложение закрывается; пользователь
завершает системную установку и запускает его обычным способом. Файлы программы
и запись удаления остаются под управлением установщика. Linux требует обработчик
DEB или `sudo apt install ./ФАЙЛ.deb`; удаление пакета сохраняет профиль.

Переносной desktop проверяет digest, подпись манифеста, платформу и каждый распакованный
файл. Для установки нужна доступная для записи родительская папка программы.
После подтверждения помощник запускается из кэша, ждёт закрытия старого процесса,
заменяет приложение и ждёт подтверждения запуска каталога от новой версии.
При сбое запуска он возвращает прежнее приложение. Данные пользователя находятся
вне папки программы. Прерванная загрузка продолжается после входа; отмена удаляет
её и файлы подготовки.

## Проверять изменения

Debug использует ID `app.spotygram.dev`, релиз — `app.spotygram`.
Они устанавливаются рядом и не разделяют сессию. Только debug может
использовать тестовые серверы Telegram через `-PtelegramTestDc=true`.
Не переключай существующую debug-установку между серверами без очистки
данных именно этой debug-установки.

Проверки выполняются вручную: интерфейс, системный выбор файлов,
`adb logcat`, `adb shell dumpsys media_session`, `dumpsys meminfo`
и `dumpsys gfxinfo`. Тестового набора и генерируемых тестовых заготовок
в проекте нет. Наблюдения и ограничения записываются
в [журнал проверок](verification.ru.md).

На desktop запускай настоящий упакованный launcher. Проверяй нативные библиотеки,
импорт, воспроизведение, системное управление и обновление, а визуал — по реальным
снимкам обеих тем на узком и широком окне. Измеряй CPU и память процесса отдельно
в покое, при видимом плеере и при скрытом окне. Desktop `--image-only --debug`
позволяет включить изолированный тестовый DC через `-Dspotygram.telegram.test=true`;
debug-образ нельзя подписать для обычного канала обновлений. Материалы проверки
и данные аккаунта остаются вне исходников; непроверенные случаи отмечай
в журнале проверок.

Версии зависимостей и контрольная сумма Gradle зафиксированы. Для сборки
не нужны чужая медиатека, сессия Telegram или машинные пути из Git.
