# Журнал проверок

[Документация](README.ru.md) · [English](verification.md) · **Русский**

Здесь записаны наблюдения и их границы. Успешная сборка или чтение кода не
подтверждает доступ к аккаунту, качество звука или работу на физическом устройстве.
Проверки используют упакованные приложения, действия в UI и рабочие логи.
Временный код проверок, записи, снимки и данные аккаунта находятся вне исходников.

## 0.15.2 — нативная установка на компьютеры

Один готовый образ приложения теперь создаёт Windows MSI, Ubuntu DEB или macOS
DMG вместе с подписанным переносным архивом. Debug/release Android и обе полные
проверки Lint прошли. Оба release-APK сохранили ID приложения и исходный сертификат
подписи и прошли проверку выравнивания ZIP на 16 КБ.

Windows x64 прошёл тихую установку MSI, обновление с приватного MSI с настоящими
файлами 0.15.1, запуск установленной программы и штатное удаление MSI. Три записи,
импортированные старым установленным launcher, сохранились после обновления и
удаления; целостность — `ok`. Ярлык меню «Пуск» появился и удалился при деинсталляции.
Windows Installer зарегистрировал один продукт 0.15.2 в отдельной пользовательской
папке программы. Настоящий первый экран мастера и установленное приложение
просмотрены на PNG; полный интерактивный мастер на hosted runner не проходили.

Обе архитектуры macOS смонтировали настоящие DMG, показали ссылку Applications
и скопировали приложение в пользовательскую папку Applications. Установленные
launcher открыли прежний каталог и позицию. Строгая глубокая проверка ad hoc подписи
прошла до и после установки; удаление приложения сохранило профиль. Настоящие
снимки Finder, установки и приложения просмотрены.

Ubuntu 24.04 прошёл свежую установку DEB, повторную установку и удаление. Появилась
запись меню приложений с RGB-иконкой Spotygram. Установка также прошла при исходно
отсутствовавшем стандартном каталоге меню XDG. Установленная копия восстановила
две записи, избранное, состав плейлиста и позицию на паузе. Старое частичное
скачивание переносного архива удалилось после перехода на установленную копию.
Отдельный подписанный локальный пакет проверил настоящий сценарий «Закрыть и
открыть установщик»: Spotygram проверил его, завершился и открыл GDebi. Все строки
каталога и позиций после этого совпали, целостность — `ok`; временные настройки
и загрузки восстановлены. Метка версии этого пакета была приватным материалом
проверки, а не опубликованным будущим выпуском.

Проверки установленного рантайма подтвердили выбор имени пакета, отдельную подпись
и отклонение изменённых данных прежним desktop-ключом. На свежих нативных сборках
также выполнены проверки установки и отката переносной версии. Этот выпуск
проверяет упаковку; авторизованный Telegram, физический звук, батарея и прочие
границы ниже повторно не проверялись. Windows Authenticode и Apple notarization
не настроены; открытие пакета Linux зависит от рабочего стола пользователя,
альтернатива через `apt install` описана в руководстве.
Отдельная проверка хранилища ключей на переиспользованном образе Windows завершилась
с нативным кодом ошибки heap `0xC0000374`. Итоговая проверка MSI использовала
установленные приложения; этот запуск не подтверждает надёжность авторизованного
Telegram на Windows.

## 0.15.1 — аудит хранения, воспроизведения и обновления

Debug, оба release-APK Android, debug/release Lint и образ Linux собрались успешно.
Windows x64 и macOS Intel/Apple Silicon собраны и запущены на штатных GitHub runners.
ID приложения Android, сертификат APK, публичный ключ desktop-обновлений и схема 5
SQLite сохранены. Оба APK прошли проверку подписи и выравнивания ZIP на 16 КБ;
оба macOS-пакета — строгую глубокую проверку ad hoc подписи.

Подписанный x86-64 APK установлен поверх 0.15.0 на Android 16. После проверок все
исходные треки, источники, плейлисты, их состав и строки загрузок/кэша совпали;
целостность SQLite — `ok`. Проверены Opus, перемотка, пауза/продолжение, 0,3× и 4×.
Запись на паузе в 112 602 мс вернулась на 112 610 мс после переключения треков.
Настоящие экраны просмотрены в светлой/тёмной теме: ENG при 400 dp, RU при 320 dp
и масштабе шрифта 1,3. Временные настройки и закладки восстановлены. Во время этих
проверок лог падений приложения пуст; холодные сбои системы эмулятора были до них.

Linux проверен с локальными записями и аппаратным рендерером Mesa. Сохранённое место
длинной записи восстановилось, перемотка сработала, повторные MPRIS Play оставляли
воспроизведение активным. На Windows/macOS импортированы три записи, наблюдались
воспроизведение и сохранение позиции; просмотрены реальные снимки библиотеки и
плеера. Системные хранилища сохранили, повторно прочитали и удалили временный ключ.
Linux и все три штатных desktop-цели проверили подписанные архивы и отклонили
изменённые байты приложения.

После публикации Linux 0.15.0 получил настоящий GitHub Latest через «Проверить
обновления → Скачать и установить → Перезапустить и установить». Запущенное
приложение стало 0.15.1; обе записи, избранное и состав плейлиста совпали с исходной
базой. Позиция на паузе осталась 1 172 086 мс, целостность — `ok`; приложение убрало
загрузку, подготовку и файлы помощника. Все шесть опубликованных сборок и `SHA256SUMS`
совпали с серверными хешами GitHub.

Windows и обе архитектуры macOS прошли установку с подтверждением запуска и три
сценария отката: заблокированное подтверждение, подписанный образ с нерабочим
launcher и повреждённый каталог. Проверка Windows выявила дочернюю JVM, державшую
JAR после завершения launcher; остановка собственного дерева процессов исправила
откат. Ошибка каталога не подтверждала успешное обновление и не стирала исходные данные.

Проверка кода убрала запрос на каждый плейлист, повторные проверки файлов-алиасов
и копирование списка загрузок после каждого файла. Также проверены отмена локального
импорта, транзакционное удаление, ожидание каталога и устаревшие ID файлов Telegram
после выхода. Это выводы о коде и корректности работы, без замеров больших каталогов.
Существующий Telegram-каталог из 536 записей открылся, но повторить авторизованный
стриминг не удалось: приватная тестовая связка ключей Linux была заблокирована.
Сессия и исходный ключ сохранены; результаты с авторизацией ниже относятся к **0.15.0**.

## 0.15.0 — одно приложение на четырёх платформах

Общие экраны, ресурсы, Haze Glass, каталог, Telegram, правила кэша и очередь
скомпилированы для Android и desktop. Android сохранил Media3; desktop использовал
libmpv и закреплённые нативные сборки с Java 21. SQLite остался на схеме 5.

Debug, оптимизированная release-сборка Android и обе полные проверки Lint прошли.
Подписанный x86-64 APK установлен поверх 0.14.0 без сброса данных. Исходные треки,
плейлисты, их состав и источники совпали; целостность SQLite — `ok`.
Проверены MP3/Opus, пределы скорости, медиакнопки, настройки и сохранённые файлы.
Настоящие экраны просмотрены в обеих темах: ENG при 400 dp, RU при 320 dp и масштабе
шрифта 1,3. После исправления форматирования настроек лог падений приложения пуст.
Повторяющиеся холодные ANR System UI эмулятора происходили до проверок приложения.

Windows x64 и обе архитектуры macOS запускали упакованные launcher на штатных
GitHub runners. Импортированы три WAV; позиция воспроизведения росла, плеер
открывался, длинная запись сохраняла место. PNG просмотрены. Проверки встроенного
рантайма охватили создание/чтение/удаление системного ключа, проверку подписанного
архива, отклонение изменённых байт, установку и откат при блокировке подтверждения
запуска. Оба macOS-пакета прошли строгую глубокую проверку ad hoc подписи.

Linux прошёл обычный сценарий «Установить обновление → Перезапустить и установить»
с временного образа 0.14.0 на подписанный 0.15.0. Две локальные записи, любимая,
состав плейлиста и позиция длинной записи сохранились; целостность — `ok`.
Неполное скачивание опубликованного обновления продолжилось; приложение убрало
загрузку, подготовку и помощника. Закрытие окна при ожидании незагруженных данных
сохранило плеер; Raise вернул окно, Quit завершил приложение.

Отдельная production-сессия Spotygram на Linux прошла вход по телефону и облачному
паролю и проиндексировала **536 записей**. Переключение телефон → QR → телефон тоже
работало. Книга начала играть до полной загрузки; проверены перемотка на 40 минут,
0,3×/4×, позиции, дослушивание, повторы одного/всех и сохранение/удаление временных
копий. Сохранённая книга играла без сети после нового запуска. Блокировка трафика
Telegram при неполной записи 1,6 ГБ сохранила ожидающую перемотку и позицию;
таймаут остановил звук без перехода дальше, возврат сети позволил продолжить.

| Конфигурация | Наблюдавшиеся память процесса / CPU |
| --- | --- |
| Штатные runners Windows/macOS, локальные записи | Около 240–320 МиБ RSS; на паузе 0–1,5% одного ядра |
| Windows runner, видимый плеер с программным рендерером | Около 29% одного ядра при воспроизведении |
| Linux, аппаратный Mesa через VirtualGL, каталог Telegram | Около 597 МиБ RSS; около 19 МиБ Java heap |
| Тот же процесс Linux со скрытым окном | Около 0,2% ядра на паузе; около 2% при воспроизведении |

RSS включает память Telegram, графики и звука за пределами Java heap. Эти цифры
описывают конкретные конфигурации и не являются сравнением разных устройств.

## Границы

Физический ARM64 Android, ограничения фона OEM, качество динамиков, батарея
и физические компьютеры Windows/macOS не проверены. Авторизованный Telegram
проверен на Linux; Windows/macOS использовали локальные записи. Реальная смена
Wi-Fi, все возможные контейнеры и каталоги с сотнями тысяч разных записей не
проверялись. Упрощённое стекло старого Android проверено чтением кода, без запуска
на старом эмуляторе.
